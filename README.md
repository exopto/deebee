# Deebee
A super tiny graph database built on a philosophy of simplicity, ownership, and sugar. It is native to Python and does not have a query language by design, each method meant to read like standard English and integrate with traditional Python structures.

Like all graph databases, it is built on nodes (known as boxees) and pointers, but it introduces a third concept: children. While traditional pointers simply point from one node to another, children are subservant and meant to be highly integrated with the parent. Children and parents have no special roles aside from being linked to each other and having a variety of helper functions to access each other, meaning children can have multiple parents and vice versa. For example, `box.add(y)` adds an arbitrary number of children passed as arguments. This allows for a tighter and more structured database, which can even emulate a traditional table structure. Arbitrary pointers can still be made alongside this structure (`box.point(y)`). If `y` is a string, it will be converted into a box which can then be accessed with box.find(y), and if it is a Box or UUID to a Box, then a connection will simply be made.

## API
Deebee's source code is entirely concentrated into one Python file, although it will later be ported to Rust for speed and idiomaticity. Rather than describing each method of `Box` in this README, it is best to see the power and simplicity of Deebee in action.

Note: Examples are coming soon, but for now the API is still changing. Below is an example using a version of the API that may be outdated.

```python
from deebee import Box
# You may also construct `Box` simply through Box("Cat", ["American Shorthair"])
canis = Box.create("Canis Genus", ["Coyote", "Ethiopian Wolf", "Red Wolf", "Gray Wolf"]) # Second argument is sugar for `add` as shown below
canis.find("Gray Wolf")[0].add("Domestic Dog")


Box.create("Cat", ["American Shorthair"])
felis = Box("Felis")
Box.master_search("Cat").link(felis) # Master search searches the entire database (no variable needed!) Link is the inverse of `add` and can also accept a string.
felis.add("Jungle Cat", "African Wildcat", "Sand Cat")
shorthair = felis.find("American Shorthair")[0]

shorthair.add("Pumpkin", "Luna", "Lil' Wayne") # Get searches all descendants by default for a match.
shorthair.add("Luna") # Oh no! Two cats with the same name? What will you do?
print(shorthair.find_all("Luna")[1]) # Crisis averted. Find_all returns a list.
luna_2_id = shorthair.find_all("Luna")[1].id # `find_all` should return descendants in a primogeniture-like order. Let's save the second Luna's UUID just in case.

for shorthair_cat in shorthair:
    print(f"Hello, {shorthair_cat}!")

# Now, the grand finale!
felidae_id = felis.link("Felidae").id
Box.master_find(felidae_id).link("Feliformia") # ID lookups are faster as they are a simple dict lookup rather than a loop.
Box.master_find("Feliformia").link("Carnivora")
Box.master_search("Carnivora").add("Caniformia")
Box.master_search("Caniformia").add("Canidae")
Box.master_search("Canidae").add("Canis")
```
